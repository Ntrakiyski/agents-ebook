## Style Summary

The style is a dark, hand-drawn blackboard/whiteboard explainer aesthetic:

- matte black or near-black background
- white hand-drawn text and arrows
- thick rounded strokes
- simple icons instead of detailed illustrations
- large negative space
- minimal text, usually one idea per visual
- colored outlines to distinguish roles, steps, categories, or capability types
- simple left-to-right or top-to-bottom flow
- playful but still technical

## Palette

Use mostly white and soft gray on black, with a small set of bright accent
colors:

- white for primary text, arrows, and icons
- gray for supporting text
- green for starting/available/confirmed states
- yellow for planning/specification states
- red for risk, human intervention, or hot/active work
- purple for search/retrieval/alternate paths
- blue for AI, system, review, or checkpoint states
- orange for tools/build work

## Composition Rules

- Keep pages airy. Do not fill every part of the canvas.
- Prefer a single central path, dependency map, or handoff timeline.
- Use labels sparingly. The diagram should make the structure obvious before the
  reader reads the words.
- Use repeated shapes for repeated concepts: nodes, checkpoints, tokens,
  agents, tools, human approvals.
- Use icons only when they clarify a node type.
- Avoid photorealistic detail for core system diagrams.
- Avoid UI artifacts from the references, such as mouse cursors, editor
  selection boxes, cropped side panels, or screenshot borders.

## Fit For This Book

This style is especially useful for:

- capability ladders
- ATLAS checkpoints
- chapter "what's next" maps
- agent loops
- tool-call flows
- context pipelines
- RAG pipelines
- human/AI handoffs
- permissions and approval gates
- solo-to-team progression maps

It supports the book's desired reading experience: uncluttered, simple,
progressive, lightly gamified, and easy to understand at a glance.
